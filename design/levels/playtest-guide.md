# 사람 플레이테스트 안내 (웹 프로토타입, 17스테이지)

목적: 흥미도 모델(`interest-model.md`)이 예측한 막힘·지루함 지점이 실제와 맞는지 확인하고, 가중치를 보정할 기록(`telemetry-mapping.md`)을 모은다.
대상 빌드: `7lucky` b03a654 기준 17스테이지 (석상 수 문 3개, 레버 2개 포함). 번호는 바뀔 수 있으니 분석은 스테이지 이름으로 한다.

## 1. 준비 (진행자)

```bash
export PATH="/c/Program Files/nodejs:$PATH"
STATS_TOKEN=<아무 문자열> node server/src/index.mjs
#   테스터 주소   http://localhost:8787/play/                ← 같은 출처라 기록이 자동으로 쌓인다
#   대시보드      http://localhost:8787/dashboard#token=<토큰>
```
- 다른 PC의 테스터는 `cloudflared tunnel --url http://localhost:8787`로 받은 주소 + `/play/` (자세한 것은 `server/README.md`)
- 테스트 전에 화면 아래 **"기록 전송 켬"** 인지 확인. 꺼져 있으면 기록이 남지 않는다
- 같은 브라우저로 여러 사람을 받으면 클리어 기록과 플레이어 ID가 섞인다 → 사람마다 **시크릿 창**을 새로 연다
- 웹 프로토타입만 따로 띄울 때 `python -m http.server 8777`은 이 PC에서 8777 포트가 이미 쓰이고 있을 수 있다. 기록이 필요하면 항상 `/play/`를 쓴다

## 2. 테스터에게 할 말 (이것만)

> 한 번에 7걸음만 걸을 수 있는 퍼즐입니다. 1번부터 순서대로 해 주세요. 힌트("풀이 보기")와 되돌리기는 언제든 써도 됩니다.
> 그만하고 싶으면 그때 그만두셔도 됩니다. 생각나는 건 소리 내어 말해 주세요.

- **규칙을 미리 설명하지 않는다.** 스테이지 힌트 문구가 가르치는지 보는 것도 테스트다
- 막혀도 도와주지 않는다. 테스터가 물으면 "힌트 버튼을 써도 돼요"까지만
- 40~50분이면 17스테이지를 대부분 끝낸다. 시간 제한을 말하지 않는다
- 목표 인원: **5명 이상** (5명 미만인 스테이지는 보정에 쓰지 않는다)

## 3. 스테이지별로 볼 것

예측 흥미도 I와 모델이 의심하는 점이다. 진행자는 해당 스테이지에서 아래 질문의 답을 메모한다(시각, 한 줄).

|---|---|---|---|---|

| 2 | 늦게 도착하기 | 0.63 | "일부러 돌아간다"를 스스로 떠올리는가 | 시간, Undo |
| 3 | 돌이 된 몸 | 0.46 ▼ | **KEEP과 발판을 한꺼번에** 배우는 게 버거운가 (모델: 난이도 급상승) | 시간·재시작이 2보다 크게 뛰는지 |

| 11 | 한 번만 버티는 바닥 | 0.65 | 금 간 바닥 규칙(지나가면 무너짐, 7번째에 서면 굳음)을 메시지로 이해하는가 | `crumble` 뒤 재시작 |

## 4. 끝난 뒤 질문 (2분)

1. 가장 재미있던 스테이지와 이유
2. 가장 짜증났던 스테이지와 이유 (억울함 / 지루함 / 몰라서)
3. "아!" 하고 풀린 순간이 있었던 스테이지
4. 규칙 중 끝까지 헷갈린 것

답은 `design/levels/playtest/<날짜>-notes.md`에 사람별로 적는다(이름 대신 P1, P2…). 대시보드의 플레이어 ID와 연결하려면 시작 시각을 함께 적는다.

## 5. 기록 넘기기

```bash
T=<토큰>; mkdir -p reports/telemetry
curl -H "Authorization: Bearer $T" "http://localhost:8787/api/export/attempts.csv?client=web-proto&since=<날짜>" -o reports/telemetry/attempts.csv
curl -H "Authorization: Bearer $T" "http://localhost:8787/api/export/events.jsonl?client=web-proto&since=<날짜>" -o reports/telemetry/events.jsonl
```
- `reports/`는 커밋하지 않는다. 레벨 디자인이 보정 스크립트로 읽어 `interest-curve.html`에 실측 I를 겹쳐 그린다
- 테스트 중에 스테이지를 바꾸지 않는다. 바꾸면 빌드 문자열(`proto-<레벨 해시>`)이 바뀌므로 `build` 필터로 나눠 본다

## 6. 성공 기준 (이번 테스트로 판단할 것)

- 8(레버 소개)에서 시간·재시작이 뛰고 9(멈춰 세우는 석상)에서는 v0보다 덜 막힌다 → 모델 맞음. 8이 실제로도 가장 지루하거나 어렵다면 6(숫자 문) 보강안을 적용
- 7의 시간·idle이 3·8 수준이다 → 자동 난이도 보정(`dAdj`) 필요
- 6이 20초 안에 끝나고 테스터가 숫자 문을 "그냥 지나갔다"고 말한다 → 숫자 문 소개 스테이지 수정
- 13~15에서 HUD 석상 수를 보고 푸는가 → 아니면 화면 표시 강화 요청(게임플레이/UI)
