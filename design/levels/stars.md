# 3별 구조 (B안 확정, 2026-11-09 사용자 결정)

대상: 50스테이지 후보(`experiments/batch1~5`, 손질 반영 60b256a). 계산: 솔버 `minBodies`, 그리고 몸 예산 3으로 이길 수 있는 몸 수를 모두 찾는 BFS(상태 60만 개 한도, 50개 모두 한도 안에서 끝남).

## 0. 확정 정의

| 별 | 조건 (한 번의 시도 안에서) |
|---|---|
| ★1 | 클리어 |
| ★2 | ★1 + 풀이 보기(H)를 한 번도 쓰지 않음 + 쓴 몸 수 = `expected.minBodies` |
| ★3 | ★2 + 되돌리기(Z)·재시작(R)을 한 번도 쓰지 않음 |

- **시도**: 스테이지에 들어와(`level_start`) 클리어할 때까지. 같은 스테이지를 다시 시작(선택 화면에서 다시 들어옴, 클리어 뒤 다시 하기)하면 새 시도이고 조건을 처음부터 센다. 시도 중의 재시작은 같은 시도다(텔레메트리 정의와 같음)
- **기록**: 스테이지마다 지금까지의 최고 별 수만 남긴다(진행 기록 v2, 스테이지 이름 기준). 별은 줄지 않는다
- **잠금 없음.** 별은 수집과 자랑용
- 판정에 필요한 값은 모두 이미 있다: `levels.json` `expected.minBodies`, 시도 중 `hints`·`undos`·`restarts`·`bodiesUsed`(텔레메트리 `level_clear`와 같은 값). 서버도 `level_clear`만으로 별을 다시 계산할 수 있다
- **`winBodies`는 넣지 않는다.** 판정에는 `minBodies`만 쓴다. 최소 몸 수로만 깰 수 있는 25개(2장 표)에서 ★2가 "클리어 + 풀이 보기 안 씀"과 같아지는 것은 의도한 동작이다(그 스테이지들은 ★3이 차이를 만든다). 화면에서 "이 스테이지는 몸 n개가 최소"를 보여 주려면 `minBodies`로 충분하다
- 경계: 몸을 모두 잃으면(`level_fail`) 재시작이나 되돌리기를 해야 하므로 그 시도는 ★3을 받을 수 없다. 최소 몸 수가 3보다 작은 스테이지에서 몸 하나를 구멍에 헛되이 잃고 깨면 쓴 몸 수가 늘어 ★2를 못 받는다

### 0.1 화면 문구 (제안, 다국어 형식이 정해지면 옮김)

- 결과 화면: "★ 클리어" / "★ 풀이를 보지 않고 형제 n명으로" / "★ 한 번에" (조건을 못 채운 별은 흐리게, 조건 문구는 늘 보이게)
- 스테이지 선택: 행성마다 북두칠성 일곱 별(4장), 별 수만큼 밝기. 7장의 여덟 번째(50 원형 제단)는 북극성

## 1. 검토 결론 (결정 전 기록)

- **최소 몸 수(★2)는 계산할 수 있고 의미가 있다.** `levels.json`의 `expected.minBodies`가 이미 그 값이다(export가 JS 솔버로 씀)
- **최단 걸음 수(★3, par)는 별로 쓸 수 없다.** 몸 하나는 항상 정확히 7걸음을 걷고 끝난다(7번째 걸음이 몸을 끝냄, 그 전에 끝나는 것은 구멍 낙하뿐인데 그러면 몸을 하나 더 쓴다). 그래서 최소 몸 수로 깬 해의 걸음 수는 **언제나 7 × 몸 수**다. 50개 중 45개가 정확히 그렇고, 다른 5개(43~45, 49, 50)도 진흙 칸 수만큼 버튼 수가 줄 뿐이다. ★3 = ★2가 된다
- **★2가 갈리는 스테이지는 25개뿐이다.** 나머지 25개(대부분 최소 몸 3)는 최소 몸 수로만 깰 수 있어서, 깨기만 하면 ★2가 붙는다
- **추천: B안** — ★1 클리어, ★2 풀이 보기 없이 최소 몸 수로 클리어, ★3 ★2에 더해 되돌리기·재시작 없이 한 번에. 50개 모두에서 세 별이 서로 다르다. 별은 진행을 잠그지 않는다(수집·자랑)

## 4. 별자리 (북두칠성 테마)

- 장(행성)마다 스테이지 7개 = **북두칠성 별 7개.** 스테이지의 별 수(★1~3)가 그 별의 밝기. 장의 일곱 별이 모두 켜지면(각 ★1 이상) 그 행성의 별자리가 완성되고, 모두 ★3이면 가장 밝게 빛난다
- 7장은 8스테이지: 50번째 원형 제단 = **북극성.** 여섯 행성의 국자가 가리키는 별. 서사와도 맞는다(국자 = 7번째 걸음의 정렬, 아트 바이블 "1–6걸음은 별 하나씩, 7번째는 국자가 완성되는 정렬")
- 합계 150별. 잼 범위에서는 잠금 없음. 잠금이 필요해지면 "각 장 첫 스테이지는 언제나 열림, 50번은 6장까지 ★1 이상"처럼 별 수가 아닌 클리어로 거는 것을 권한다

## 5. 데이터와 계산 (검토 당시 제안 — 확정은 0장)

- `levels.json` `expected`: `minBodies`(있음), `moves`(있음, 최소 몸 해의 행동 수). 추가 제안: `winBodies`(이길 수 있는 몸 수 목록, 예 `[2,3]`) — ★2가 자동인지 화면에서 알려 줄 때만 필요. **`parSteps`는 넣지 않는다**(= 7 × minBodies, 진흙 판은 버튼 수만 다름)
- 계산 위치: `export-levels.mjs`(JS 솔버, 이미 minBodies를 씀). `winBodies`는 위 BFS를 export에 넣으면 50개 전체 수십 초. Unity `LevelVerifier`가 C# 솔버로 같은 값인지 확인
- 판정(B안): 클리어 시 `bodiesUsed == minBodies && hints == 0` → ★2, 여기에 `undos == 0 && restarts == 0` → ★3. 텔레메트리 `level_clear`에 이미 `bodiesUsed`·`hints`·`undos`·`restarts`가 있어 서버에서도 같은 값을 다시 계산할 수 있다(`stars` 필드 추가는 선택)
- 저장: 진행 기록 v2(이름 기준)에 스테이지별 최고 별 수
- 화면: 결과 화면 별 3개와 조건 문구, 스테이지 선택의 별자리(장별 7개 + 북극성)
