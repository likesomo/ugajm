## 숫자 없는 일곱 걸음·흔적 상태

**채운 별=걸은 수, 빈 별=남은 수**. 처음부터 발치 호에 빈 별7개를 둔다. 첫 별은 출발점이 아닌 첫 유효 이동의 도착점이다. 여섯째 이후 마지막 빈 별만 1.4초 주기로 맥동한다. 일곱째에 모두 찬 호와 숫자 없는 하늘 북두칠성이 연결된다. 같은 칸을 반복해 바닥 흔적이 겹쳐도 호는 일곱 개 순서를 유지한다. 숫자 문은 문에 새긴 N과 채운 별 수를 세어 맞춘다.

별 흔적 v2의 상태 언어를 실제 3D 리뷰 상태로 재현했다: 단일=현 형제색 경로, KEEP=굳은 별자리+실제 선돌 위 별, SWITCH=기존 경로+두 색 매듭 이음매, 피날레=세 색 경로와 선돌 별에서 하늘 국자로 이어지는 세 광선. KEEP 뒤 다음 형제는 원래 출발점, SWITCH 뒤 다음 형제는 현재 칸에서 빈 호를 받는다. 선택 중 실제 Unity 모델의 옅은 고스트 두 개를 출발점/현재 칸에 동시에 보여 준다.

리뷰 별은 Unity 메시/LineRenderer로 렌더했다. 현재 Art 셰이더에는 완성된 production 별 흔적 구현이 없으므로 이미 production 셰이더가 동작한 결과라고 주장하지 않는다. `star-trail/v2/` 상태를 실제 보드에서 검토하기 위한 캡처 전용 표현이며 정식 계약 연결은 아래와 같다.

프로필·조작 ID·튜토리얼 버전별 seen을 저장한다. 재시작·Undo·언어 변경은 seen을 되돌리지 않는다. KEEP/SWITCH는 첫 **세 번의 확정 선택**까지만 각 결과 설명 한 줄, 이후 선돌/매듭 아이콘+K/X만 남긴다. 취소·실행 불가는 횟수를 늘리지 않는다. 메뉴>조작법은 수동 재생하며 seen을 바꾸지 않는다. 목업은 설명 체크박스와 선택 횟수 저장으로 두 밀도를 확인한다. 세 번째 형제 종료·추락·클리어처럼 규칙상 선택이 없는 상태에는 표시하지 않는다.

접근성: 걸음 숫자 표시(기본 꺼짐), 움직임 줄이기, 언어. 숫자 켜짐은 호 옆 한 곳에만 걸은 수/일곱을 표시한다. 움직임 줄이기는 맥동 대신 이중 테두리, 하늘 광선 대신 즉시 완성. 형제 구분은 색 외에 원/마름모/획과 점 상태 형태를 병용한다. 메뉴 체크박스는 구조 목업이며 실제 게임 설정 저장/별 렌더 전환은 후속 구현이다.

## 구현 메모 — View 전용

실제 이벤트는 `GameSession.Updated(SessionUpdate)`와 `Presented(State)`다. HudView는 전달 State의 유효 걸음·현재 형제·선택 필요·승패를 읽고 표시 상태만 결정한다. 도메인 판정과 Keep/Switch 명령은 기존 Core/Contracts를 호출한다. Undo/Reset/언어 변경 때 전체 상태를 재표현해 호와 경로를 일치시킨다.

`StarTrailMap`은 2W×H RGBA 계약: layer0 RGB step1–7 비트가 호 채움 원본, bit7=KEEP 선돌; layer1 A EndSwitch=매듭, EndBridge=가라앉은 별, EndFell/EndVanish=추락/소멸. `_StarTrailState=(currentBody,phase,finale,0)`의 phase0/1/2/3은 play/choose/win/lose. `_StarTrailPulse` newest/seventh awaken, `StarTrailPreset.awakenSeconds`·`finaleSeconds`와 애니메이션을 맞추고 리뷰 시간 상수를 production의 별도 진실로 만들지 않는다. `_StarTrailColors`는 TileSet 형제색과 UI를 맞춘다.

UiTheme는 FontRole·ink/panel/gold/stone·별·Dipper·얇은 프레임을 공급한다. HudView는 밀도와 조건부 노출, BoardView 측 별 흔적 View는 경로/매듭/선돌 별의 월드 표현을 담당한다. 발치 호는 배우 앵커에 붙고 동일한 유효 걸음 원본을 공유한다. seen·접근성은 프로필에 저장하고 퍼즐 리플레이 해시에 섞지 않는다.

## 검증 범위와 남은 확인

실제 Unity 리뷰 빌드와 56개 PNG 저장 확인. 숨김 Windows 창의 ScreenCapture가 실패한 초기 시도는 최종 결과에 세지 않았고 최종은 RenderTexture→ReadPixels로 직접 렌더했다. DOF/Panini stripping 및 Unity 종료 시 기존 JobTemp 경고는 로그에 보존한다. production 자산/씬/카메라 변경은 남기지 않는다.

HTML 검사는 moss/frost/carved×KO/EN×9=54화면에서 안전 여백24px, 실제 보드 투영과 HUD 비겹침, 텍스트 넘침과 상호작용을 확인한다. production UiLayoutCheck가 HTML을 검사할 수는 없으므로 **docs/architecture.md 14.6의 같은 기하 규칙을 별도 검사**한 결과다. production 전체 검사 통과나 1920×1080 런타임 적용을 주장하지 않는다. 정식 적용 때 최대 보드·23번 긴 문구·KO/EN·1920×1080을 다시 검사한다.

사용자 확인: 720p에서 별 일곱 개를 셀 수 있는지, 일곱 재질에서 빈 별/찬 별이 구분되는지, 두 고스트로 KEEP/SWITCH의 다음 출발점을 이해하는지, 작은 선택이 형제에 충분히 가까운지. 범용 앵커 회피·게임 설정/힌트 저장·실제 세션 연결은 후속 구현이다. 본 작업은 실제 아트 위 UI 목업이며 production Unity UI 코드는 변경하지 않았다.

## UI v3 — 실제 GameSession 선택 프로토타입 (2026-11-11)

사용자의 “KEEP/SWITCH를 더 명확하게 안내하고 실제 Unity에서 확인” 요청을 반영했다. v2의 작은 K/X 아이콘을 다음 형제 머플러색 테두리의 두 갈래 카드로 바꾸고, 선돌/매듭 그림·한국어/영어 이름·큰 키 배지·결과 한 줄을 함께 보여 준다. 선택 중에는 보드를 살짝 어둡게 하고 형제 주변 링과 “걷기 잠김” 안내를 표시한다. 보드 전체 투영 영역의 좌우 여백을 비교해 패널을 놓고 형제 높이에 맞춰 제한한다. 처음 설명 상자도 보드 바깥 여백에 둔다.

호버/키보드 포커스는 한 선택지만 미리 보여 준다. KEEP는 현재 칸의 반투명 선돌과 출발점의 다음 형제, 둘 사이 점선이다. SWITCH는 현재 칸의 다음 형제와 바통 매듭이다. 첫 세 번 확정 전에는 양쪽 결과 설명이 보이고 그 뒤에는 포커스한 카드만 설명한다. 세션 메모리 기준이며 프로필 영속 저장은 정식 HUD 이식 때 처리한다.

별 흔적 v2의 형제색 별빛 점·직각 빛줄기·굳은 별자리·선돌 별·매듭·일곱째 각성을 실제 저장된 BoardShapeA/ChapterPreset 보드 위에 리뷰 전용 Unity Graphic으로 구현했다. 화면 위 합성이 아니라 Unity가 보드 RenderTexture와 투영된 리뷰 도형을 함께 렌더한다. production StarTrail 셰이더 구현과는 별개다. 발치 일곱 별은 기본 16px로 키웠고 형제색 바깥별/빈 중심을 사용한다. 6걸음의 마지막 별은 17~23px로 맥동한다. 일곱 실제 행성 재질 위 720p 캡처를 남긴다.

`Art/Test/UiV3/ChoiceReview.unity`는 독립 `SevenSteps.Art.Review` 어셈블리의 참고 프로토타입이다. `ReviewChoiceController`, `ChoicePanelView`, `GhostPreviewView`, `StarTrailReviewView`, `FootStarsView`가 실제 `GameSession(IBoardPresenter)`에 연결된다. 프로젝트 설정에 맞는 Unity Input System과 UI 입력 모듈을 쓴다. K/X·마우스·터치 버튼·Tab/Enter·Z가 같은 명령 경로를 사용하며 확정 연출은 0.38초 이내다. 선택 여부는 세션 이벤트의 Status.Choose만 읽고 구멍/출구 판정을 중복 구현하지 않는다. 정식 씬/HUD/규칙은 수정하지 않는다.
