# 로그라이크 성장 요소 설계 검토 — 숫자 연금술사 v2

- 작성일: 2026-11-06
- 대상: v2 프로토타입 (`src/`), 컨셉 `design/gdd/game-concept.md`
- 목적: 런 안의 성장(빌드)과 런 사이의 성장(메타)을 추가하기 전에, 현재 구조의 빈틈과 후보안, 우선순위를 정리한다.

---

## 1. 현재 구조 진단

| 로그라이크 요소 | 현재 상태 | 평가 |
|---|---|---|
| 런 단위 구조 (짧은 판, 영구 사망) | 7층 1판, 사망 시 처음부터 | ✅ 있음 |
| 매 판의 변화 | 시드별 문화권 배치와 적 숫자 | △ 약함. 판마다 "새로운 빌드"가 나오지 않음 |
| 런 안의 성장 선택 | KEEP 보상이 고정 순서 (%, Σ, 행동 +1) | ❌ 선택지가 없음. 매 판 같은 성장 |
| 빌드 정체성 | 시작 숫자 하나 | △ 숫자는 다르지만 그 외 차별화 없음 |
| 위험 vs 보상 경로 | 없음 (층 순서 고정, 예보만 있음) | ❌ |
| 상점·경제 | 물약, 부적 2종 | △ 골드 쓸 곳이 부족 |
| 메타 진행 (판 사이) | 없음 | ❌ |
| 난이도 확장 | 없음 | ❌ |

**핵심 진단**: 지금은 "숫자 퍼즐 7연전"에 가깝다. 로그라이크의 재미인 **"이번 판에는 이런 빌드가 나왔다"**가 없다. KEEP의 보상이 고정되어 있어서 신앙이 쌓이는 과정이 매 판 같다.

**지켜야 할 것**: 성장 요소가 Pillar 1(숫자는 도구)과 Pillar 2(결과는 미리 보임)를 깨면 안 된다. "공격력 +10%" 같은 숫자 밖의 스탯 성장은 v1의 실패(숫자가 패시브가 됨)를 반복한다. **모든 성장은 "내가 만들 수 있는 숫자"를 바꾸는 형태여야 한다.**

## 2. 런 안의 성장 (빌드) 후보

### A. 연산 부적 (Relic) — ⭐ 최우선
층을 클리어할 때마다 **부적 3개 중 1개**를 고른다. 부적은 "새 연산"이나 "판정 규칙"을 바꾼다.

| 부적 | 효과 | 테마 근거 |
|---|---|---|
| 거울 | 적 숫자 뒤집기 연산 추가 (`12 → 21`, `41 → 14`) | 숫자 회문 |
| 제곱근 | 완전제곱수에 √ 연산 (`49 → 7`) | 수학 |
| 반쪽 | 짝수를 반으로 (`÷2`) 맨손 연산 추가 | 수학 |
| 八方 | 결과에 8이 포함되면(18, 28, 88) 축복 판정 | 동양 發 |
| 십삼일 | 연산 결과가 13이면 문화권과 무관하게 소멸 | 서양 13 |
| 삼세판 | 같은 적에게 3번 연속 연산하면 3번째는 무료 | 한국 삼세판 |
| 쌍둥이 수 | 연산 하나가 같은 숫자의 적 모두에게 적용 | 같은 운명 |
| 행운 동전 | 맨손 ±1이 ±2 중 선택 가능 | 서양 행운 동전 |

- **장점**: 빌드 다양성의 핵심이다. 모든 효과가 "만들 수 있는 숫자"를 바꾸므로 필러에 부합한다. 미리보기 UI를 그대로 재사용한다.
- **KEEP/SWITCH와의 관계**: 부적은 숫자를 바꿔도 유지된다. 그래서 "이 부적 조합에는 어떤 숫자가 맞는가"라는 **새 SWITCH 동기**가 생긴다. (예: 거울 부적을 얻으면 큰 수 13이 유리해진다)
- **비용**: 부적 8종 기준 약 6~8시간. 연산을 `applyOp`에 추가하고 판정 훅을 `resolve`에 추가하면 된다.

### B. 숫자 진화 (KEEP 보상의 분기) — ⭐ 우선
고정된 신앙 보상(%, Σ, 행동 +1)을 **신앙 단계마다 2지선다**로 바꾼다.

| 신앙 | 선택지 예시 (7 기준) |
|---|---|
| 1 | `%` 나머지 해금 **또는** 맨손 ±1이 ±2로 |
| 2 | Σ 수비학 **또는** **두 번째 피연산자** 7 → {7, 1} (연산마다 둘 중 선택) |
| 3 | 행동 +1 **또는** **숫자 진화** 7 → 77 (피연산자가 커짐, 큰 적 처리 특화) |

- **장점**: KEEP의 의미가 "같은 보상을 기다림"에서 "내 숫자를 어떻게 키울지 고름"으로 바뀐다. 오래 믿을수록 그 숫자만의 빌드가 생긴다. 컨셉 문서의 "7 → 77 → 777" 판타지를 실현한다.
- **위험**: 피연산자가 둘이 되면 연산 버튼 수가 2배가 된다. UI는 "피연산자 토글 하나 + 연산자 버튼"으로 해결한다.
- **비용**: 약 4~6시간

### C. 갈림길 지도 — 중간
예보(고정 순서) 대신 **다음 층을 2갈래 중 고른다**. 예: "서양 대성당(일반)" vs "동양 사원(정예: 적 +1, 부적 보상 확정)".

- **장점**: KEEP/SWITCH와 강하게 맞물린다. "내 숫자에 맞는 길로 갈까, 숫자를 바꿔서 보상 많은 길로 갈까?"
- **위험**: 결정이 두 개(길, 숫자)로 늘어 제단 화면이 복잡해진다. 잼 범위에서는 단순 2지선다로 제한한다.
- **비용**: 약 3~4시간

### D. 배신당한 숫자의 유품 — ⭐ 우선 (작고 효과 큼)
배신당한 숫자를 쓰러뜨리면 **그 숫자의 전용 부적**을 떨어뜨린다. (예: 배신당한 7 → "7의 유품: 연산 결과가 7의 배수면 행동 +1")

- **장점**: SWITCH에 **보상**이 생긴다. 지금 시뮬에서 SWITCH가 손해인 경향(KEEP 85% vs 상황 판단 61%, 숫자 3 기준)을 설계로 보정하는 장치다. "버린 숫자는 돌아온다"가 위협이자 기회가 된다.
- **비용**: A를 만든 뒤라면 1~2시간

### E. 적 특성 — 중간
적에게 규칙을 하나씩 붙여 퍼즐을 다양하게 만든다.

| 특성 | 효과 | 테마 |
|---|---|---|
| 귀신 | 4가 되면 소멸하지 않고 14로 부활 (동양) | 死 → 要死 |
| 분열 | 짝수가 되면 반으로 나뉜 두 적이 됨 | 수학 |
| 소수 수호 | 소수일 때는 ×, ÷ 불가 | 소수 |
| 시계 | 매 턴 숫자가 +1씩 커짐 | 카운트다운 |

- **비용**: 특성당 약 1시간. 잼에서는 2~3종을 권장한다.

### F. 이벤트 층 — 낮음
점집, 수비학자, 도박장 같은 비전투 선택 이벤트. 테마 전달력은 좋지만 텍스트 작성량이 많아 잼 후반에 시간이 남으면 추가한다.

## 3. 런 사이의 성장 (메타) 후보

| 후보 | 내용 | 비용 | 판단 |
|---|---|---|---|
| **숫자 해금** | 처음에는 3·7·8만 열림. 조건 달성 시 해금 (예: "8로 동양 층 3번 클리어 → 9 해금", "서양 층에서 13 SWITCH 없이 클리어 → 13 해금") | 2~3시간 (localStorage) | ⭐ 권장. 첫 판의 선택 부담을 줄이고 재도전 동기를 준다 |
| **숫자 도감** | 숫자별 최고 기록, 엔딩, 타임라인 갤러리 | 2시간 | 권장. 엔딩 타임라인이 이미 있으므로 저장만 하면 된다 |
| **부적 해금** | 런에서 처음 본 부적을 다음 판부터 보상 풀에 추가 | 1시간 | A 이후 권장 |
| **액운 단계 (난이도)** | 클리어할 때마다 다음 판에 저주 추가 (적 카운트다운 −1, 4층마다 보스 등) | 3시간 | 잼 이후 |
| 영구 스탯 강화 | HP 영구 증가 등 | - | ❌ 비권장. 숫자와 무관한 성장이라 Pillar 1 위반, 퍼즐 긴장감도 무너진다 |

## 4. 우선순위와 로드맵

필러 부합도, 결정(KEEP/SWITCH)과의 시너지, 비용을 기준으로 정했다.

| 순위 | 항목 | 이유 | 예상 |
|---|---|---|---|
| 1 | **A. 연산 부적** (6~8종, 층마다 3택1) | 빌드 다양성의 핵심. 로그라이크다움의 대부분을 만든다 | 6~8h |
| 2 | **D. 배신당한 숫자의 유품** | SWITCH에 보상을 줘서 결정 균형을 설계로 해결 | 1~2h |
| 3 | **B. 숫자 진화** (신앙 2지선다) | KEEP을 빌드 선택으로 바꿈 | 4~6h |
| 4 | **메타: 숫자 해금 + 도감** | 재도전 동기, 첫 판 단순화 | 3~4h |
| 5 | E. 적 특성 2~3종 | 퍼즐 다양성 | 2~3h |
| 6 | C. 갈림길 지도 | 결정이 겹칠 위험이 있어 1~5 이후 검증 | 3~4h |
| 보류 | F 이벤트, 액운 단계 | 잼 이후 | - |

**잼 범위 권장안 (약 15~20시간)**: 1 + 2 + 3 + 4. 성장 축이 세 개 생긴다. 부적은 숫자와 무관하게 쌓이고, 진화는 KEEP하면 깊어지고, 유품은 SWITCH하면 얻는다.

## 5. 리스크와 검증 계획

| 리스크 | 대응 |
|---|---|
| 연산이 늘어 화면이 복잡해짐 (Pillar 2) | 연산 버튼 상한 8개. 부적 연산은 조건이 맞을 때만 활성 표시. 미리보기 UI 유지 |
| 조합 폭발로 밸런스 붕괴 | `tools/sim.mjs`에 부적 선택 봇(무작위 / 탐욕)을 추가하고, 부적별 채택 시 승률 차이를 리포트. ±10%p 이상 차이 나는 부적은 조정 |
| 3·KEEP 같은 지배 전략이 굳어짐 | 숫자별 전용 부적과 유품으로 보정. 시뮬에서 전략별 승률 분포를 계속 감시 |
| 봇 승률만 보고 재미를 판단 (v1의 교훈) | 각 단계마다 **사람 플레이테스트**를 먼저 한다. 시뮬은 수치 검증에만 쓴다 |
| 수학 미궁이 너무 어려움 (평균 3.5~4.5수) | 부적 "반쪽(÷2)"이나 수학 층 목표 확장(💀 0 + 완전수 6, 28)으로 완화 |

## 6. 결정이 필요한 질문
1. 부적은 **층 클리어마다 3택1**(빠른 성장)인가, **상점 구매**(경제 연동)인가? 권장은 3택1이고, 상점은 회복 위주로 둔다.
2. 숫자 진화에서 **피연산자 2개**를 허용할 것인가? 가장 재미있지만 UI 비용이 가장 크다.
3. 메타 해금으로 **첫 판의 숫자를 3개로 줄일 것인가**? itch.io 첫인상(선택지 단순화)에는 유리하지만, 6개 숫자를 바로 보여주는 탐색 재미는 줄어든다.
