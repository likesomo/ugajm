# Game Concept: 일곱 걸음 (Seven Steps) — 초안

> Unity 게임잼 출품용 신규 아이디어. 기존 웹판 "숫자 연금술사"(`game-concept.md`)와 별개 문서다.
> v1 플레이테스트 교훈("숫자가 뭘 하는지 모르겠다")을 반영해, **7이라는 숫자를 매 걸음 화면에 보이는 자원**으로 만든다.

## Core Identity
| 항목 | 내용 |
|---|---|
| Elevator Pitch | 나는 한 번에 딱 7걸음만 걸을 수 있다. 7번째 걸음이 닿는 칸만 세상을 바꾼다. 7걸음이 끝나면 몸은 돌이 되고, 나는 출발점에서 다시 깨어난다. |
| Core Verb | 걸음 세기 (경로 길이 계산), 남기기 (석상을 어디에 둘지) |
| Core Fantasy | 운명이 정해 준 일곱 걸음을 정확히 계산해 세상에 흔적을 새기는 순례자 |
| Unique Hook | 1~6번째 걸음은 그냥 지나가고 **7번째 걸음만** 스위치·문·적과 상호작용한다. 퍼즐의 답이 "어디로 가나"가 아니라 "몇 걸음째에 도착하나"다 |
| Genre | 턴제 그리드 퍼즐 |
| Platform | Unity (WebGL 빌드로 itch.io 업로드, PC 빌드 선택) |
| Estimated Scope | Small (게임잼 48–72시간, 1–2인) |

## 핵심 규칙
| 요소 | 규칙 |
|---|---|
| 걸음 | 상하좌우 1칸 = 1걸음. 캐릭터 발밑에 남은 걸음 `7 → 0`이 항상 표시된다 |
| 행운의 7번째 걸음 | 7번째로 밟은 칸에 **행운 도장**이 찍히고 그 칸의 효과가 발동한다. 1~6번째 걸음은 효과 없이 통과 |
| KEEP / SWITCH | 7걸음을 다 쓰면 고른다. KEEP: 그 자리에 석상을 남기고 다음 몸은 현재 출발점에서. SWITCH: 석상 없이 그 자리가 새 출발점이 된다. 둘 다 몸 1개를 쓴다. 마지막 몸이면 선택 없이 석상 |
| 석상 | 벽처럼 막고, 발판을 계속 누르고, 구덩이에 두면 다리가 된다. 석상이 남는 것이 다음 시도의 도구다 |
| 기회 | 스테이지마다 몸 수 제한(기본 7개). 다 쓰면 재시작 |
| 클리어 | 출구 칸에 **정확히 7번째 걸음**으로 도착 |
| 되돌리기 | 걸음 단위 Undo 무제한, `R` 스테이지 재시작 (퍼즐 장르 필수) |

## 타일 (잼 범위 8종)
| 타일 | 7번째 걸음으로 밟으면 | 그냥 지나가면 |
|---|---|---|
| 바닥 | 아무 일 없음 (석상만 남음) | 통과 |
| 벽 | — | 막힘 |
| 구덩이 | 낙하 (몸 1개 손실) | 낙하. 석상이 있으면 다리 |
| 발판 | 연결된 문 열림 (몸이 떠나면 닫힘 → 석상으로 고정) | 효과 없음 |
| 금 간 바닥 | 무너져 구덩이가 됨 (길을 끊는 용도) | 통과 |
| 숫자 문 `N` | — | **N번째 걸음일 때만** 통과 가능 |
| 얼음 | 미끄러지는 동안은 걸음을 세지 않음 | 벽에 닿을 때까지 미끄러짐 (1걸음) |
| 출구 | 클리어 | 통과 (아무 일 없음) |

숫자 문과 얼음이 "몇 걸음째인가"를 계산하게 만드는 핵심 장치다. 숫자 문은 걸음 수 자체를 화면에 드러내 v1의 문제(숫자가 안 보임)를 직접 해결한다.

## 확장 후보 (시간이 남으면, 하나만)
- **순찰자**: 내가 1걸음 갈 때 정해진 경로로 1칸 움직인다. 7번째 걸음으로 순찰자 칸을 밟으면 순찰자가 석상이 된다. 1~6번째에 닿으면 몸 손실.

## 스테이지 흐름 (목표 15스테이지)
| 구간 | 스테이지 | 가르치는 것 |
|---|---|---|
| 1장 걸음 | 1–4 | 7걸음, 7번째 도착, 석상이 벽이 됨 |
| 2장 흔적 | 5–8 | 발판 + 석상 고정, 구덩이 다리 |
| 3장 숫자 | 9–12 | 숫자 문, 얼음으로 걸음 수 맞추기, 금 간 바닥 |
| 최종 | 13–15 | 7×7 맵, 몸 7개를 모두 계획해서 써야 하는 종합 퍼즐 |

## Pillars
1. **세어서 푼다**: 정답은 언제나 걸음 수로 설명할 수 있다. 운 요소 없음.
2. **흔적이 도구다**: 실패한 시도도 석상으로 남아 다음 시도를 돕는다.
3. **7은 항상 보인다**: 남은 걸음, 숫자 문, 행운 도장이 매 걸음 화면에 드러난다.

## Anti-Pillars
- 실시간 조작·반사신경 요구 없음 (턴제만)
- 랜덤 생성 맵 없음 (손으로 만든 스테이지만)
- 스토리 컷신 없음 (스테이지 이름과 짧은 문구로 대신)

## Unity 구현 방향
| 항목 | 결정 |
|---|---|
| 시점 | 3D 쿼터뷰 로우폴리 (석상이 쌓이는 모습이 잘 보임). 시간이 부족하면 2D 탑다운으로 |
| 코어 | `SevenStepsCore` 순수 C# 클래스(MonoBehaviour 아님). 모든 상태 변경은 `Dispatch(state, cmd)` 하나로만. 시간·난수를 쓰지 않으므로 결정론적 |
| 스테이지 데이터 | 텍스트 맵(`#` 벽, `.` 바닥, `o` 구덩이, `3` 숫자 문 등) → ScriptableObject로 임포트 |
| 표현 | 뷰는 상태를 읽기만 함. 걸음마다 트윈, 7번째 걸음에 도장 이펙트와 효과음 |
| 검증 | 에디터 메뉴에서 BFS 솔버로 모든 스테이지 풀이 가능 여부와 최소 몸 수를 확인 → 공통 report 한 장으로 출력. 명령 목록 리플레이로 같은 상태 재현 |
| 빌드 | WebGL (itch.io 브라우저 플레이), 권장 해상도 1280×720 |

## 일정 (48시간 기준)
| 시간 | 할 일 |
|---|---|
| 0–8h | 코어 규칙 + 텍스트 맵 + 솔버 (화면 없이 검증) |
| 8–20h | Unity 뷰, 입력, Undo, 스테이지 1–8 |
| 20–32h | 숫자 문·얼음·금 간 바닥, 스테이지 9–15 |
| 32–42h | 연출(도장, 석화), 사운드, 타이틀/엔딩 |
| 42–48h | 플레이테스트, 난이도 순서 조정, WebGL 빌드 업로드 |
