# Game Concept: 일곱 걸음 (Seven Steps)

> Unity 게임잼 출품작. 기존 웹판 "숫자 연금술사"(`game-concept.md`, 이 브랜치에는 없음)와 별개 문서다.
> v1 플레이테스트 교훈("숫자가 뭘 하는지 모르겠다")을 반영해, **7이라는 숫자를 매 걸음 화면에 보이는 자원**으로 만든다.
>
> **규칙의 기준은 코드다.** 웹 프로토타입 `prototypes/seven-steps/src/core.js`와 이를 옮긴 Unity `SevenSteps.Core`(`unity/Assets/_Project/Scripts/Runtime/Core/Rules.cs`)가 같은 결과를 내도록 검증되어 있다(`unity/Tools/unity.sh verify`). 이 문서와 코드가 다르면 코드를 따르고 이 문서를 고친다.
> 2026-11-07 갱신: 초안의 규칙 중 구덩이·금 간 바닥·발판·몸 수를 코드 기준으로 바꾸고, 출발점 소멸(vanish) 규칙과 v0 구현 현황을 추가했다.

## Core Identity
| 항목 | 내용 |
|---|---|
| Elevator Pitch | 나는 한 번에 딱 7걸음만 걸을 수 있다. 7번째 걸음이 닿는 칸만 세상을 바꾼다. 7걸음이 끝나면 몸은 돌이 되고, 나는 출발점에서 다시 깨어난다. |
| Core Verb | 걸음 세기 (경로 길이 계산), 남기기 (석상을 어디에 둘지, 출발점을 옮길지) |
| Core Fantasy | 운명이 정해 준 일곱 걸음을 정확히 계산해 세상에 흔적을 새기는 순례자 |
| Unique Hook | 1~6번째 걸음은 그냥 지나가고 **7번째 걸음만** 칸과 상호작용한다. 퍼즐의 답이 "어디로 가나"가 아니라 "몇 걸음째에 도착하나"다 |
| Genre | 턴제 그리드 퍼즐 |
| Platform | Unity 6 (WebGL 빌드로 itch.io 업로드, Windows 빌드 선택) |
| Estimated Scope | Small (게임잼, 다중 에이전트 팀 — `agents/README.md`) |

## 핵심 루프
1. 출발점에서 몸 하나로 깨어난다. 남은 걸음 `7`.
2. 상하좌우로 걷는다. 걸음마다 남은 수가 줄고, 지나간 칸에 걸음 번호가 남는다.
3. 7번째 걸음이 닿은 칸의 효과가 발동한다 (아래 표).
4. 몸이 남아 있으면 출발점에서 다음 몸이 깨어난다. 앞선 몸이 남긴 석상·다리·무너진 바닥은 그대로다.
5. 출구를 정확히 7번째 걸음으로 밟으면 클리어. 몸을 모두 쓰면 실패.

## 핵심 규칙
| 요소 | 규칙 (코드 기준) |
|---|---|
| 걸음 | 상하좌우 1칸 = 1걸음. 막힌 쪽으로는 움직이지 않고 걸음도 쓰지 않는다. 캐릭터 위에 남은 걸음 `7 → 0`이 표시된다 |
| 행운의 7번째 걸음 | 7번째로 도착한 칸에서만 효과가 발동한다. 1~6번째 걸음은 바닥·발판·출구를 그냥 지나간다 (구덩이·금 간 바닥은 예외, 타일 표 참고) |
| KEEP / SWITCH | 7번째 걸음이 바닥·발판·얼음·숫자 문 칸에서 끝나면 고른다. **KEEP**: 그 자리에 석상을 남기고 다음 몸은 현재 출발점에서. **SWITCH**: 석상 없이 그 자리가 새 출발점이 된다. 둘 다 몸 1개를 쓴다 |
| 마지막 몸 | 남은 몸이 1개면 선택 없이 석상이 되고, 다음 몸이 없으므로 곧바로 실패 |
| 출발점 소멸 (vanish) | 7번째 걸음이 **현재 출발점** 칸에서 끝나면 석상도 선택도 없이 몸만 1개 사라진다 |
| 석상 | 벽처럼 이동을 막고 얼음 미끄러짐도 멈춘다. 같은 글자의 발판 위에 있으면 그 문이 계속 열린다. 한 번 놓으면 사라지지 않는다 (Undo 제외) |
| 몸 수 | 스테이지마다 다르다 (현재 2~5개, 데이터에 없으면 기본 7). 화면에 원으로 표시 |
| 클리어 | 출구 칸에 **정확히 7번째 걸음**으로 도착 (얼음에서 미끄러져 도착해도 된다) |
| 실패 | 몸을 모두 씀. 실패 화면에서 되돌리기 또는 재시작 |
| 되돌리기 | 명령 단위 Undo 무제한 (몸이 바뀐 뒤에도 이전 몸으로 돌아간다). `R` 스테이지 재시작 |
| 풀이 보기 | BFS 솔버의 최단 풀이를 **스테이지 처음부터** 보여 준다 (현재 상태에서 이어지는 풀이가 아님) |

## 타일
맵 글자는 `parseLevel()`과 `Level.Parse()`의 범례와 같다.

| 글자 | 타일 | 7번째 걸음으로 도착하면 | 1~6번째 걸음일 때 |
|---|---|---|---|
| `.` `S` | 바닥 / 시작점 | KEEP 또는 SWITCH (현재 출발점이면 vanish) | 통과 |
| `#` | 벽 | — | 막힘 |
| `o` | 구덩이 | 몸이 떨어져 **다리**(`=`)가 된다. 몸 1개 사용, 선택 없음 | 떨어져 몸 1개 손실, 아무것도 남지 않음. 다음 몸이 출발점에서 깨어남 |
| `=` | 다리 (구덩이·금 간 바닥이 메워진 칸) | 바닥과 같음 | 통과 |
| `a` `b` `c` | 발판 | 바닥과 같음 (KEEP으로 석상을 두면 같은 글자 문이 열림) | 통과. **플레이어가 서 있어도 문은 열리지 않는다.** 석상만 발판을 누른다 |
| `A` `B` `C` | 문 | 열려 있으면 바닥과 같음 | 같은 글자 발판 중 하나에 석상이 있으면 열림, 아니면 막힘 |
| `x` | 금 간 바닥 | 그 자리에서 굳어 영구 **다리**가 된다. 몸 1개 사용, 선택 없음 | 통과할 수 있지만, 밟고 **떠나는 순간** 뒤에서 무너져 구덩이가 된다 |
| `1`~`7` | 숫자 문 `N` | 바닥과 같음 (`7` 문만 해당) | **N번째 걸음으로만** 들어갈 수 있다. 다른 걸음이면 막힘 |
| `~` | 얼음 | 미끄러져 멈춘 칸 기준으로 판정 | 다음 칸이 막힐 때까지 미끄러지고, 몇 칸을 가도 **1걸음**. 벽·석상·닫힌 문·번호가 맞지 않는 숫자 문 앞에서 멈추고, 구덩이로는 미끄러져 떨어진다 |
| `E` | 출구 | 클리어 | 통과 (아무 일 없음) |

숫자 문과 얼음이 "몇 걸음째인가"를 계산하게 만드는 핵심 장치다. 숫자 문은 걸음 수 자체를 화면에 드러내 v1의 문제(숫자가 안 보임)를 직접 해결한다.

### 초안에서 바뀐 점 (2026-11-07)
프로토타입 커밋에 변경 이유가 기록되어 있지 않아, 마지막 열은 리드가 코드와 스테이지에서 추정한 설계 의도다. 다르면 고쳐 주세요.

| 항목 | 초안 | 현재 (코드) | 설계 의도 (추정) |
|---|---|---|---|
| 구덩이 + 7번째 | 낙하, 몸 손실. 석상이 있으면 다리 | 몸 자체가 다리가 됨 | 석상을 구덩이로 옮기는 수단이 없어, 7번째 걸음으로 몸을 던지는 쪽이 규칙 하나로 설명된다 |
| 금 간 바닥 | 7번째에 무너짐, 그냥 지나가면 통과 | 지나가면 무너짐, 7번째로 서면 굳음 | "한 번만 버티는 바닥"이 경로를 끊는 장치가 되고, 7번째 걸음이 다시 고정 수단이 된다 |
| 발판 | 7번째 걸음으로 밟으면 문 열림, 떠나면 닫힘 | 석상만 누름 | "흔적이 도구다" 기둥과 맞춤. 문을 열려면 몸 하나를 남겨야 한다 |
| 몸 수 | 기본 7개 | 스테이지별 2~5개 | 작은 맵에서 7개는 시행착오가 너무 쉬움 |
| 출발점에서 7번째 | 언급 없음 | vanish (몸만 잃음) | 출발점에 석상이 서면 다음 몸이 깨어날 수 없음 |

## 새 기믹 (2026-11-07 리드 결정, 근거: `design/levels/gimmick-backlog.md`, `analysis-v0.md`)
| 기믹 | 상태 | 규칙 요약 | 넣을 곳 |
|---|---|---|---|
| **석상 수 문** | **구현됨** (core.js·C#, 7lucky `4ed38fe`, 맵 글자 `Q` + 레벨 필드 `statueCount`) | 문에 적힌 수 N과 지금 서 있는 석상 수가 **정확히 같을 때만** 열린다. 다리(구덩이·금 간 바닥 봉인)는 세지 않는다 | 3스테이지: 하나만 남겨라(N=1) / 열쇠가 되는 몸(N=1) / 남기기 전에 지나가라(N=0). 순서는 아래 "스테이지 순서 (승인)" |
| 레버 (뒤집히는 벽) | 규칙 확정, 구현은 석상 수 문 스테이지 반영 후 (코어) | 레버를 7번째 걸음으로 밟으면 모든 뒤집힘 벽이 뒤집힌다. 1~6번째는 통과 | 7과 8 사이 + 얼음 결합 |
| 순찰자 | 보류 | 내가 1걸음 갈 때 정해진 경로로 1칸. 7번째로 밟으면 석상, 1~6번째에 닿으면 몸 손실 | 시간이 남으면 최종장 앞 |

- 석상 수 문은 HUD에 **현재 석상 수**를 반드시 보여 준다 (세는 부담을 화면에 드러냄, 기둥 3).
- 레버 규칙 확정 (2026-11-07): 레버 칸이 출발점일 때 그 칸에서 7번째 걸음을 마치면 기존 규칙대로 **vanish(몸만 잃음), 레버는 당겨지지 않는다.** 출발점 7번째에는 어떤 칸 효과도 없다는 규칙 하나로 통일. 스케치 3개는 이 규칙으로도 풀린다 (`design/levels/gimmick-backlog.md` 2절).
- 석상 수 문 칸도 출발점이 될 수 있다 (SWITCH). 그 뒤 석상 수가 바뀌어 문이 닫혀도 몸은 그 칸에서 깨어난다. 화면은 닫힌 문 칸 위의 캐릭터·석상을 함께 그려야 한다.

### 스테이지 순서 (2026-11-07 승인, 근거: `design/levels/proposal-statue-door.md`)

### 목표 15스테이지
13~15는 미구현. 7×7 맵에서 몸을 모두 계획해서 써야 하는 종합 퍼즐로, 레벨 디자인 에이전트(`agents/level-design.md`)가 만든다. 사람 플레이테스트 후 1~12의 순서와 몸 수도 다시 조정한다.

## Pillars
1. **세어서 푼다**: 정답은 언제나 걸음 수로 설명할 수 있다. 운 요소 없음.
2. **흔적이 도구다**: 실패한 시도도 석상·다리로 남아 다음 시도를 돕는다.
3. **7은 항상 보인다**: 남은 걸음, 걸음 번호 발자국, 숫자 문, 행운 도장이 매 걸음 화면에 드러난다.

## Anti-Pillars
- 실시간 조작·반사신경 요구 없음 (턴제만)
- 랜덤 생성 맵 없음 (손으로 만든 스테이지만)
- 스토리 컷신 없음 (스테이지 이름과 짧은 문구로 대신)
