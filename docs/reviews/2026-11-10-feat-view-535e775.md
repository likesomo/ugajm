# 검토: feat/view 535e775 (별 일곱 고리, 피날레 건너뛰기 N1, UseQuad N2)

검토자: 아키텍트, 2026-11-10. 26f01e0 후속. 보고: test 814/814, build-win, smoke 통과, WebGL 미검증. 코드만 읽었다.

**결론: 승인.** 질문 두 자리를 확정하고, 셰이더가 고리를 그릴 수 있도록 위치 비트를 하나 더했다(docs 15.6, Contracts `StarTrailMap`, feat/architecture).

## 질문 답
- **`_StarTrailPulse.z`**: 마지막 한 걸음 고리 맥동(0..1)으로 확정한다.
- **`_StarTrailState.w`**: 쓴 걸음(0..7)으로 확정한다. `StarTrailMap.StateVector(body, phase, finale, used)`에 선택 인자 `used`를 더했다(기존 호출은 그대로 컴파일된다).
- **고리 위치**: 셰이더는 플레이어 위치를 모르므로 층 0 A 비트 1 = 걷는 형제가 선 칸(`StarTrailMap.SetPlayer(State.Pos)`)을 더했다.
  - `StarTrail.Write`에서 `Ring`일 때(`Status.Play`) `SetPlayer(Pos)`를 부르고, `SetState`에 `Used`를 넘겨 달라(다음 커밋, gameplay-ui).
  - 프레임마다 위치를 올리지 않는다. 고리는 도착 칸에 State 기준으로 놓인다. 지금 quad도 그렇다.

## 확인한 것
- **N1 피날레 건너뛰기**: Enter·Space·클릭·탭이면 바로 끝난다.
  - 같은 Enter가 결과 패널의 "다음"까지 눌러 버리지 않는지 봤다. `GameController.Update`는 `flow.State == Result`일 때만 Enter를 받는데, 코루틴은 모든 `Update` 뒤에 재개된다. 그래서 피날레가 끝나 결과가 열리는 프레임에는 이미 그 Enter 검사를 지났고, 다음 프레임의 `wasPressedThisFrame`은 false다. 겹치지 않는다.
  - 리플레이·smoke·flowcheck는 `FinaleSpeed = 4`다.
- **N2 `UseQuad`(static, 기본 true)**: 렌더러를 끄기만 하고 맵·전역은 계속 쓴다. 셰이더 전환 때 한 줄로 끈다.
- **고리**: `StarTrail.Marks()`에 Ring 마크 7개를 더한다(진행 중일 때만, k ≤ Used이면 꺼짐). 같은 State에서 다시 계산하므로 Undo·Restart가 저절로 맞는다. 테스트 추가(StarTrailTests, StarTrailViewTests).

## 메모 (막지 않음)
- 피날레 건너뛰기 입력을 `StarTrailView`가 Input System에서 직접 읽는다. 입력은 원래 `BoardController`/`GameController`가 모은다. 지금 한 곳뿐이라 괜찮지만, 입력이 더 생기면 `BoardView.SkipFinale()` 같은 호출로 바꾸는 쪽이 9장(MVC)에 맞다.
- WebGL(`smoke-webgl`, FPS)은 26f01e0과 함께 병합 전에 측정한다.
