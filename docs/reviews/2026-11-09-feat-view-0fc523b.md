# 검토: feat/view 0fc523b (7b2f259 BoardController 정리, 텔레메트리 걸음 수)

검토자: 아키텍트, 2026-11-09. 코드 읽기.

**결론: OK (계약 위반 없음).** 지난 권장(61180ac) 반영됨.

- **텔레메트리**: 막히지 않은 이동의 `step`과 착지 칸을 코어의 착지 이벤트(`Win`/`Fall`/`Bridge`/`Seal`/`Vanish`/`Choose`/`Stone`/`Step`, telemetry.js 순서)에서 읽는다. 진흙 비용을 다시 계산하지 않는다(9장 규칙 로직은 Core에만). 막힌 이동은 telemetry.js대로 `Used + 1`. 착지 이벤트가 없거나 `StepIdx <= Used`면 예외(코어 계약 위반을 바로 드러냄, 단정적). 이 이벤트들은 모두 코어에서 `stepIdx`를 싣는다(Rules.Step 확인).
- **`GameAudio`**: 이벤트 → 효과음, 음량은 `SettingsChanged` 구독(Dispose에서 해제). `ApplyMaster`가 마스터 음량의 한 곳. 클립이 없으면 소리 없이 넘어감 — 공유 폴더 미연결은 외부 자원이라 허용(9장 예외 범주).
- **`HintProvider`**: Core `Solver` 호출 + 스테이지별 캐시, 범위 검사. 메인 스레드 동기 풀이는 예전과 같다(WebGL 스레드 금지).
- **`MessagePresenter`**: 순수 C#, 이벤트 → 문구 표. 규칙 판단 없음(`Status.Choose`·`Bump` 여부는 상태·이벤트 읽기).
- `BoardController`는 세 클래스를 조립·호출만 한다. 매 프레임 할당 없음.

## 사소 (막지 않음)
- `MessagePresenter`의 "다음 걸음이 7번째"는 `StepIdx == 6`일 때만이다. 진흙 앞에서 `StepIdx == 5`(다음이 진흙이면 7번째)는 알려 주지 않는다. 안내 문구라 지금은 괜찮고, 7장(진흙) 플레이테스트에서 헷갈리면 보강.
