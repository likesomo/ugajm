# 검토: feat/view 365d5bb (리허설 B: 챕터 카드가 첫 방향키를 삼킴)

검토자: 아키텍트, 2026-11-10. 코드 읽기 검토. 게임플레이/UI 보고: test 764/764, 헤드리스 Chrome에서 1스테이지 카드 상태 → 방향키 한 번 → 카드 닫힘 + 이동 확인.

**결론: 승인.**

- 원인 진단 맞음: `board.InputBlocked`가 오버레이가 하나라도 있으면 보드 입력을 버렸고, 행성 진입마다 뜨는 챕터 카드도 오버레이다. 로딩·페이드는 무관(11.1 `IsLoading`은 씬 로드가 끝나면 풀림).
- 수정: **챕터 카드가 유일한 오버레이일 때만** 보드를 막지 않고, 보드 키가 눌리면 `BackNavigator`로 카드를 닫는다. 같은 프레임에 보드가 그 키를 처리하므로 Update 순서와 무관하게 키가 사라지지 않는다. 설정·언어·결과 오버레이는 그대로 보드를 막는다(오버레이 위 키가 보드로 새지 않음). 마우스는 카드가 화면 전체를 덮고 클릭으로 닫히므로(보드는 `PointerOverUi`로 무시) 그대로.
- 메모: 보드 키 목록이 두 곳(`AnyBoardKeyPressed`, `BoardController.Update`의 분기)에 있다. 지금은 일치하지만 키를 추가할 때 한쪽만 고치면 카드가 열린 채 이동이 된다. 다음에 손볼 때 키 → 명령 표 하나로 합친다.
- 씬 플로우 파일 `ChapterIntroController`의 요약 주석("board input waits")이 이제 틀리다 — 씬 플로우가 고친다.
