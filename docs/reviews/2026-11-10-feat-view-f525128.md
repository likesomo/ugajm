## 3216c4d `UiLayout`
- 14.8 계약 그대로: `UiLayoutRule` 플래그 6개, `secondary`, `exempt`, `reason`, `[DisallowMultipleComponent]`, 자손에 퍼지지 않음. `Ui.Exempt`는 `None`·빈 이유를 예외로 막고, 두 번 부르면 규칙과 이유를 합친다. `Ui.Secondary`는 체이닝.
- scene-flow 37a146b와 같은 패치라 두 브랜치가 모두 7lucky에 들어가도 같은 변경으로 합쳐진다(내용이 달라지면 충돌하니 둘 중 한쪽만 고칠 것).

## f525128 계약 대조
- **14.4 판·버튼**: `FitButtonSkin`이 버튼 프레임을 `pixelsPerUnitMultiplier` 2.5로 그려 border 20 → 8, 라벨을 border + 8 안쪽으로 늘린다. `FrameBorder`가 실제 스프라이트 border를 읽으므로 border 12 스프라이트도 코드 변경 없음. 평면(border 0) 기본 버튼은 테마 스프라이트 border로 자리를 비워 두고, x 쪽은 기존 여백보다 줄이지 않아(아이콘 자리) 여러 번 불러도 같은 결과. 판은 `Ui.Plate`(평면 패널색, 알파 0.9 ≥ 0.75, raycast 끔).
- **14.2**: 본문 22, 조작 안내·상태 라벨 18은 `Ui.Secondary`. 결과 별 조건·버튼 22.
- **14.6 보드 영역**: `HudView.BoardFrame`(316,222 648×398)은 HUD 조각들에서 16/8 떨어진 남는 칸, `BoardView.FitCamera`가 그 비율로 높이·너비를 맞추고(`halfY / frame.height`, `halfX / frame.width / aspect`) 카메라를 틀 중심으로 옮긴다. 기존 `0.52`·`0.9`·`lift 0.05`를 같은 식으로 일반화한 것이라 맞다.
- **14.7 모달**: 결과 Overlay 알파 0.72(≥ 0.6), raycast 켬.
- `HudView.Refresh`: 메시지가 비면 메시지와 옆 칸(`sidePanel`)을 숨김. `msg`는 null이면 이미 예외라 `msg.Length` 안전.
- `result.star2_*` 줄바꿈을 ko/en 문자열에 넣음: 쓰는 곳은 `ResultView` 한 곳뿐이라 다른 화면 영향 없음. 테스트 기대값도 갱신.

## 메모 (막지 않음)
- **N1** `FrameBorder`가 기준 PPU를 100으로 고정한다. 실제 식은 `sprite.pixelsPerUnit / canvas.referencePixelsPerUnit`이다. 지금 모든 캔버스가 기본값 100이라 결과는 같지만, 캔버스가 있을 때는 `img.canvas.referencePixelsPerUnit`(없으면 100)을 쓰면 안전하다.
- **N2** `BoardViewport`는 16:9 전제(CanvasScaler match 0.5). 16:10(Windows 1280×800)에서는 HUD 배치가 달라져 틀이 몇 픽셀 어긋날 수 있다. 14.9에서 16:10은 경고만이므로 지금은 충분.
- **N3** `BoardFrame`은 HUD 배치를 바꾸면 손으로 맞춰야 하는 상수다. `UiLayoutCheck`(scene-flow)의 14.6 검사는 이 상수가 아니라 **실제 HUD 사각형과 보드 투영**으로 해야 상수가 틀렸을 때 잡힌다. 14.6에 적어 둠.
