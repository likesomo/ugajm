# 검토: feat/scene-flow c474b03 (level_start.via 규칙: 고른 진입은 첫 진입이어도 select)

검토자: 아키텍트, 2026-11-10. 코드 읽기 검토. 씬 플로우 보고: test 768/768(텔레메트리 골든 213 트레이스·11984 이벤트 일치), scene-validate 0/0.

**결론: 승인.** docs 11.2 진입 경로 문단·변경 기록은 아키텍트가 갱신함.

- `TakeVia = announced ?? (FirstPending ? firstVia : select)` — docs/telemetry.md 3장의 via 정의(e953eb0, 리드 결정)와 같다: 고른 진입(지도·목록·타이틀 시작)은 `select`, 고르지 않은 바로 진입(이어하기·에디터 시작)은 첫 진입이면 `boot`, 실행 인자는 `url`.
- `TitleFlowController`가 `EntryTracker`를 필수 인자로 받고 `CanGoToGame` 확인 **뒤에** `Announce(select)` → `GoToGame`. 전이가 거부되면 알림도 남지 않는다.
- 테스트: `TitleFlowControllerTests`·`AppFlowContractTests` 갱신, `TelemetryGoldenTests`가 트레이스 최상위 `via`를 첫 `level_start`에 쓴다(서버 골든 `manual-first-entry-select` 추가분과 맞춤, 리드 허락).
- 메모: `Announce` 뒤 `GoToGame`이 예외로 끝나면(로드 중 등, `CanGoToGame`이 막으므로 실제로는 없음) 알림이 다음 진입까지 남는다. 단정 규칙상 그 예외는 버그 신호라 따로 막지 않는다.
