# 검토: feat/scene-flow c513108 (최소 UI 씬 플로우 몫: 메뉴, 1회 안내, 접근성 설정)

검토자: 아키텍트, 2026-11-11. 기준 c0e8bb2 계약(docs 4.4, 11.3.2, 14.11). 코드만 읽었다. 테스트(832/832)·scene-validate·smoke는 scene-flow 보고 수치이고, 이 검토에서 다시 돌리지 않았다.
범위: `Flow/TutorialTracker.cs`, `Flow/MenuController.cs`, `UI/MenuPanel.cs`, `UI/SettingsPanel.cs`, `GameController.cs`, `UiLayoutCheck.cs`(메뉴 등록), 문자열 ko/en, 테스트 2개.

**결론: 승인.** Contracts 변경은 없다. 계약 11.3.2를 그대로 쓴다.

## 계약 대조
- **센다/안 센다**: `TutorialTracker.Apply`는 `SessionUpdateKind.Present`만 센다.
  - 막힌 이동은 Feedback이라 이동 안내를 소비하지 않는다.
  - 로드·Undo·Restart·Replay는 Rebuild/Snap이라 seen이 변하지 않는다.
  - 확정은 `u.Prev.Status == Choose`인 Keep/Switch만 센다. 거부된 K/X는 Feedback이라 이 분기에 오지 않는다. 4.4 "확정 횟수는 세션 구독자 한 곳"과 같다.
- **저장**: `SaveTutorialStore`가 `SaveSystem` 명령만 부르고 필드를 직접 쓰지 않는다. `-newplayer` 초기화는 Contracts 쪽에서 된다.
- **검사 실행 제외**: smoke·`-replay`·flowcheck·titlecheck 실행은 `MemoryTutorialStore(allSeen: true)`를 쓴다. 그래서 프로필을 건드리지 않고, 스크린샷에는 평소 HUD가 나온다. 11.3.2의 "리플레이·smoke 실행 제외"보다 넓은데, 맞는 쪽이다.
- **메뉴**: 오버레이 스택을 쓴다(입력 차단, Esc 닫힘). 다른 오버레이 위에서는 열리지 않는다.
  - 막 알파 0.74에 `raycastTarget`이 켜져 있어 14.7을 지킨다.
  - 풀이 보기는 기존 `BoardController.ShowHint`라서 별(H 집계)과 텔레메트리 `hint`가 기존 H와 같다.
  - 조작법 다시 보기는 seen을 바꾸지 않는다(11.3.2).
- **세션 구독**: `BoardController.session`은 한 번 만들어지므로 `Updated += tutorial.Apply`가 스테이지마다 바뀌지 않는다. `OnDestroy`에서 해제한다.

## 메모 (막지 않음)
- **C1 (gameplay-ui에 전달)** 표시 시점은 뷰가 지킨다. 트래커의 `choosing`은 Present `Updated`(일곱째 걸음 연출 시작 전)에 바로 참이 된다. 4.4대로 선택 카드와 `ShowChoiceGuide` 안내는 `Presented` 뒤에 띄운다(Snap·Rebuild면 바로).
- **C2** `MemoryTutorialStore.CountChoiceConfirm`에는 상한이 없다. 트래커가 3 미만일 때만 부르므로 지금은 영향이 없다. 테스트용 가짜가 실제 저장과 다르게 동작하지 않도록, 3에서 멈추게 해 두면 좋다.
- **C3** HUD 설정 버튼이 임시로 메뉴를 연다. gameplay-ui 메뉴 버튼이 들어오면 `SettingsRequested` 연결을 지운다(잔여 연결 두 개가 같은 메뉴를 토글하지 않게).
- **남은 등록**: 14.11 등록 화면 1~4와 6은 gameplay-ui의 Edit Mode Build 경로가 나온 뒤 등록한다. 이 브랜치는 메뉴(5)만 등록했다.
