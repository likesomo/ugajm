## 맞는 것
- **토글**: `GameController`가 화면을 만들 때 `UiStyleToggle.U5(launch)`를 한 번 묻는다. 켜져 있으면 `GameAssets.uiIcons` null을 `MissingReferenceException`으로 막는다(키트 검토 N2).
- **토글 꺼짐 경로**: `choiceView = hud`(`HudView`가 `IChoiceView`를 구현)라서 전과 같은 객체·호출이다. 바뀐 줄은 `hud.NudgeChoice()` → `choiceView.NudgeChoice()` 하나다.
- **MVC**
  - `ChoiceController`가 `IChoiceView` 인터페이스를 받는다.
  - U5의 되돌리기·다시 하기·힌트·KEEP·SWITCH는 지금 UI와 같은 컨트롤러 호출로 간다: `board.Send(Command.Undo|Keep|Switch)`, `board.Restart`, `board.ShowHint`. 그래서 규칙·텔레메트리·저장은 UI 방식과 무관하다.
  - `U5GameHud`는 이벤트만 낸다.
- **`HideClassic`**: U5가 대신하는 지금 HUD 조각만 `CanvasGroup`으로 숨긴다. 메시지, 선돌 수, 안내, 이야기, 보드 라벨은 남는다.
- **첫 방문과 다음 방문**: 첫 선택은 포커스된 글리프의 설명을 보인다. 다음부터는 포커스·hover·누르기 때만 보인다(계약 4장).
- **N1·N4**: 설명 판이 보드와 버튼을 피하게 했다. `ui5.icon.next`를 "다음 스테이지"로 바꿨다.

## 고칠 것 — R2 커밋 (리드 지시 반영, U5 기본값을 켜기 전에 필수)
- **문제**: `u5-choice-first.png`에서 KEEP/SWITCH 글리프와 설명 판이 **보드 윗벽 줄 위**에 있다. 형제에서 오른쪽으로 약 200px 떨어진 자리다.
  - 이 자리는 core가 넣은 걸음 별자리(bf5dfac, `BoardView.StepSkyBand`)가 놓이는 띠와 같다.
  - 14.11의 "선택 UI는 보드 영역 밖"에도 걸린다. 벽 줄도 보드 칸이다. `ProjectedArea`가 칸 바닥(y 0)과 배우 높이만 투영해서, 화면에서 더 높게 보이는 벽 윗면을 놓치는지 확인한다.
- **조건** (지금 카드와 U5 글리프 모두)
  1. 글리프 쌍과 설명 판은 **형제 가까이** 둔다. 형제 투영점에서 가장 가까운 후보를 쓴다.
  2. **`StepSkyBand` 밖**에 둔다. `ChoiceAvoid` 훅에 그 사각형을 넣는다.
  3. **플레이 칸 위에 두지 않는다**(`BoardView.PlayableBox` 투영). 14.11대로 보드 영역(벽 포함) 밖이 원칙이다.
     - 넓은 판에서 위·아래 띠가 모자라면 보드 좌·우를 후보로 쓴다.
     - 정말 남는 자리가 없을 때만 벽 칸 위를 허용한다. 이때는 `UiLayout.exempt = Board`와 이유를 단다(14.8, 아키텍트 검토).
  4. **캡처 확인**: 스테이지 **38**(선택)과 넓은 판 **14**(선택에 닿는 상태)를 둘 다 찍는다. `-ui5`와 토글 꺼짐 각각이고, 별자리가 보이는 상태여야 한다. 글리프·판·별자리·플레이 칸이 서로 겹치지 않는 것을 보인다.
- R2는 core bf5dfac(R1 수정 포함)가 7lucky에 들어간 뒤에 올린다.

## 메모 (막지 않음)
- **N1 `UseChoiceView` 호출 순서**
  - 주석은 "`ExplainChoices`/`ShowGuide`를 정하기 전에 부른다"이다. 이 메서드는 `ChoiceController`를 새로 만들기 때문에, 그 뒤에 부르면 설정이 사라진다.
  - 지금 호출 순서는 맞다. 다만 순서를 코드로 보장하지 않는다.
  - 고치는 법은 둘 중 하나다. 이미 설정된 뒤면 `InvalidOperationException`을 던지거나, 새 컨트롤러에 이전 값을 옮긴다.
- **N2 `BoardFrame` 재계산**: 아래 Undo·Reset 띠가 비게 된 것을 반영하는 일은 클리어 단계로 미뤘다(보고대로). 그때 별자리 띠(`StepSkyBand`)도 함께 고려한다.
- **N3 등록**: U5 HUD·선택 화면(첫 방문과 다음 방문)의 `UiLayoutCheck` 등록은 scene-flow 몫이다(계약 6장). R2 뒤에 등록하면 위 조건을 검사기가 계속 지킨다.

## 캡처 결함 정정 (2026-11-12, gameplay-ui가 찾음)

- **원인**: 헤드리스 playcapture에서는 `Capture()`가 캔버스를 1280×720 카메라로 바꾸기 전까지 HUD 캔버스가 16:9가 아니다. 그래서 선택 화면이 열릴 때 계산한 배치가 더 작은 캔버스 기준이었다.
  - 로그의 `ProjectedArea`는 305..803 × 252..515였고, 실제 보이는 보드는 약 300..990 × 170..520이다.
- **영향**
  - 40a0561의 u4·u5 선택 캡처는 실제 게임 배치가 아닐 수 있다.
  - core `step-sky-38.png`의 "카드가 별자리를 덮음"도 마찬가지다.
  - 안정된 뒤 다시 배치하면(`Choice.Refresh`) 지금 카드는 스테이지 4에서 보드 오른쪽으로 간다.
- **판정 변경**
  - bf5dfac 검토 R2의 "지금 UI 카드가 별자리를 덮는다"는 **확정이 아니다.** 고친 캡처(38·14, 토글 꺼짐)에서 겹치지 않으면 지금 UI 쪽 R2는 증거로 닫는다.
  - U5 글리프의 R2는 그대로 필요하다. 글리프는 위쪽 후보(별자리 띠)를 먼저 고른다.
- **캡처 도구 규칙**(배치를 보이는 모든 캡처에 적용)
  - 캔버스 모드·해상도를 바꾼 **뒤에** 화면 상태를 만든다.
  - 그게 안 되면 바꾼 뒤 배치하는 뷰를 모두 다시 배치하고 나서 찍는다.
  - 캡처 로그에 그 순간의 캔버스 크기(1280×720)를 함께 남겨, 다른 크기면 실패로 본다.
  - core·scene-flow 캡처도 같은 규칙을 따른다.
