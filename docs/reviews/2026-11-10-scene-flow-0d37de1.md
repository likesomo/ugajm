# 검토: feat/scene-flow 0d37de1 (QaReplay를 qa-attempts v1에 맞춤)

검토자: 아키텍트, 2026-11-10. 코드만 읽었다. scene-flow 보고: test 796/796. 기준: `docs/qa-attempts.md` v1, `qa-play.mjs`의 `replayLine()`/`runTokens()`(feat/core ca616f5).

**결론: 승인.** ca616f5 검토의 S1~S4가 모두 반영됐고, JS 기준 구현과 판정이 같다. 계약(Contracts)·규칙 변경 없음.

## 대조
- **S1 필드**: `v`, `mapHash`, `from`, `keeps`, `switches`, `level*`, `failReason`, `stateKey`, `stateHash`를 추가했다. JSON `null`은 줄에서 지운 뒤 읽어 기본값(-1 / "")으로 남긴다.
  - 정규식은 `"이름": null`만 지운다. 마지막 필드일 때 남는 쉼표도 처리한다.
  - 문자열 값 안에 그 모양이 나올 일은 없다(입력 토큰, 스테이지 이름).
- **S2 세는 범위**: `steps`/`keeps`/`switches`/`undos`/`hints`는 `k >= from`에서만 센다. `level*`은 전체 입력에서 센다. 별은 게임의 `AttemptCounts.After` 누계로 계산하므로, 하네스와 게임의 세는 방식이 어긋나면 별 차이로 드러난다.
- **S3 효과 없는 토큰**: `Send`가 `Applied`가 아니면 그 토큰에서 멈추고 불일치로 남긴다. 막힌 이동과 선택 상태가 아닐 때의 K/X는 `Rejected`, 되돌릴 것이 없는 Z는 `Ignored`다. `!`는 보내기 전에 `State.Prev == null`이면 오류다. JS `runTokens`와 문구도 같다.
- **S4 `failReason`**: 마지막 명령 이벤트를 뒤에서부터 보며 Fall/Bridge/Seal/Vanish/Stone 중 처음 만나는 것을 소문자로 쓴다(core.js `LOSS`와 같다). `fell`/`out_of_bodies`일 때만 비교한다.
- **결과(outcome) 판정**: 허용 표(clear→clear, restart→open, gave_up→open/fell/out_of_bodies)가 JS `want` 표와 같다. 판정 순서도 JS와 같다: 맵 해시가 다르면 `skipped: map changed`를 불일치로 처리하고(JS `verify`도 실패로 셈), 그다음 `v`, 스테이지 이름, `from` 범위를 본다.
- **골든 테스트**: 29 `R!HDURRRRRKZKDDR` → `10|29|3|2|15|||0|1` / `e57f027f`. 선돌이 여럿인 키 `15|16|7|0|8,16,22|||3|0`과 `keyHash("a") = e40c292c`도 고정했다. 하네스가 실제로 쓴 8줄(픽스처)은 불일치 0이고, 값을 바꾼 줄은 그 필드 불일치를 낸다.
- `QaReplayTool`이 `mapRows`로 levels.json 맵을 넘겨 `mapHash`를 비교한다.
