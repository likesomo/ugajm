검토자: 아키텍트, 2026-11-10. 코드만 읽었다. core의 `qa-play.mjs`와 `docs/qa-attempts.md`는 아직 없다. 그것이 오면 Q1~Q3을 다시 맞춘다.
범위: `Game/Flow/QaReplay.cs`, `Game/Flow/AttemptCounts.cs`(`After`), `BoardController.CountAttempt`, `EditorTools.QaReplayTool`, `BuildTools.QaReplay`, `QaReplayTests`.

**결론: 승인(골격).** 규칙 코드와 계약(Contracts) 변경 없음. 공개 API는 Game 쪽에만 추가된다(`AttemptCounts.After`, `QaReplay`·레코드 DTO). 변경 기록에 한 줄 남겼다.

## 확인한 것
- **별 판정 공유**: `AttemptCounts.After(SessionUpdate)`는 `BoardController`에 있던 docs 6.5 규칙을 글자 그대로 옮긴 것이다.
  - Undo는 `GameEventType.Undo`가 있을 때 센다.
  - Restart는 `Prev.Prev != null`일 때 센다. 시작 상태는 `Rules.NewState`의 `Prev = null`이고, Restart 결과도 `NewState`라서 이 조건이 맞다.
  - 게임과 리플레이가 같은 함수를 쓰므로 별 수가 어긋날 길이 없다.
- **헤드리스 `GameSession`**: 보드 없이 만들면 `Apply`가 잠그지 않고 `Presented`를 바로 부르므로 큐가 생기지 않는다. 그래서 입력 문자열이 하나씩 그대로 적용된다.
  - 할 일이 없는 Undo(`Ignored`)는 업데이트를 내지 않아 세지 않는다. 게임과 같다.
  - bump는 `Feedback`이라 `rejected`로 센다.
- **`bodiesUsed`**: 패배는 언제나 `NextBody`에서 `Bodies = 0`으로 끝난다(낙하도 마지막 몸일 때만 패배). 그래서 `Stars.BodiesUsed`가 `Bodies + 1`이 되고, `Min`이 이를 전체 몸 수로 맞춘다. 주석("a loss counts all bodies")과 동작이 일치한다.
- **`fell`과 `out_of_bodies` 구분**: 마지막 `Lose` 결과에 `Fall`이 있는지로 가른다. 맞다.
- **입력 오류 처리**: 잘못된 줄·레벨·글자는 예외 대신 불일치 줄로 남아 다른 시도를 가리지 않는다. 파일 자체가 없거나 JSON이 아닌 줄만 예외(종료 코드 1)다.
- **소유와 경로**: `QaReplayTool`은 `Scripts/Editor/SceneFlow`에 있고, `BuildTools`에는 위임 한 줄만 있다. 출력은 `reports/qa/`(git 밖).

## 정리 메모
- **Q1 (qa-attempts.md가 정할 것)** 지금 임시인 세 가지(재시작 글자 `!`, 해시 FNV-1a 32 of `Rules.Key`, `steps` = 적용된 이동 수이며 Undo된 이동도 셈)는 core의 `docs/qa-attempts.md`가 확정하고, 이 파일의 상수와 주석을 그 문서에 맞춘다. JS 쪽 `Rules.Key`(core.js `keyOf`)와 문자열이 바이트 단위로 같아야 해시가 맞는다. 골든값 테스트(같은 상태의 JS 해시)를 하나 두면 좋다.
- **Q2** 실제 게임에서는 이동 애니메이션 중 누른 Undo가 큐의 이동을 지우기만 하고 Undo로 세지 않는다(`GameSession.Send`). JS 하네스는 애니메이션이 없으니 해당 없지만, 나중에 실제 게임 입력 로그를 같은 리플레이에 넣는다면 이 차이를 기록 형식에서 표시해야 한다.
- **Q3 (막지 않음)** `QaReplay`가 `SevenSteps.Game`(런타임)에 있어 플레이어 빌드에도 들어간다. EditMode 테스트 어셈블리가 Editor 어셈블리를 참조하지 않아서 이렇게 둔 것으로 이해하고, 순수 C#·수 KB라 그대로 둔다.
